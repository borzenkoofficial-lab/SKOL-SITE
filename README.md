# СКОЛ — платформа программных продуктов

СКОЛ — единая витрина самостоятельных программных продуктов. Каталог построен так, чтобы новые продукты можно было добавлять без смены общей архитектуры сайта.

## Запуск и проверка
```bash
npm install
npm run dev
npm run check
npm run build
npm run preview
```

## Структура сайта
- `/` — главная платформа и каталог продуктов.
- `/tariffs` — тарифы и заявка менеджеру для СКОЛ CRM.
- `/download` — версии, журнал изменений и загрузки СКОЛ CRM.
- `/activation` — инструкция по автономной активации СКОЛ CRM.

## Принцип каталога
Сейчас в каталоге опубликован один фактический продукт — СКОЛ CRM. Блок будущих продуктов является контейнером каталога, а не заявлением о готовых или уже существующих программах. Новые карточки добавляются после появления работающего продукта и подтверждённых данных о нём.

## Источник истины по СКОЛ CRM
Тарифы, feature IDs, правила лицензирования, Device ID, формат токена и ограничения офлайн-модели сверяются с репозиторием:
`borzenkoofficial-lab/struktura-crm-source`, ветка `fix/skol-offline-licensing-2026-10`.

Матрица разрешений: `src/license-core.cjs` (объект `EDITION_FEATURES`).
Технические ограничения и пользовательский сценарий: `docs/superpowers/specs/skol-offline-license.md` и `docs/licensing/offline-license-operations.md`.

Репозиторий CRM — источник продуктовой логики и фактических возможностей. Сайт Struktura не является источником дизайна.

## Дизайн-система
Сайт использует отдельную визуальную систему SKOL Software Platform: тёмная технологическая палитра, фиолетовый/циановый спектр, лаймовый акцент, модульная сетка, каталог продуктов и единые компоненты для продуктовых страниц. Строительная айдентика и визуальные решения сайта Struktura не используются как основа.

## Продажи и лицензирование СКОЛ CRM
- Онлайн-оплата не подключена.
- Клиент выбирает тариф и формирует заявку для менеджера.
- Форма пока копирует текст заявки; доставка менеджеру через сервер или мессенджер не реализована.
- Менеджер согласовывает условия, получает Device ID и вручную выпускает ключ через License Manager.
- Закрытый ключ подписи не должен попадать в сайт, браузер или Git-репозиторий.

## Перед публичным запуском
- Настроить подтверждённый канал получения заявок менеджером.
- Опубликовать проверенный Windows installer в GitHub Releases CRM.
- Указать утверждённые цены и условия лицензирования.
- Добавлять только реальные отзывы с согласием авторов.
- Опубликовать политику обработки персональных данных и юридические документы.
