# СКОЛ — платформа программных продуктов

СКОЛ — единая витрина самостоятельных программных продуктов. Новые продукты получают отдельные карточки и подробные страницы без переделки всей платформы.

## Страницы
- `/` — главная страница платформы.
- `/catalog` — отдельный каталог программ.
- `/products/skol-crm` — подробная страница СКОЛ CRM: модули, сценарии, тарифы, техническая модель и ограничения.
- `/tariffs` — START / PRO / BUSINESS и обращение к менеджеру.
- `/download` — версии, журнал изменений и ссылка на релизы CRM.
- `/activation` — инструкция по автономной активации.

## Запуск и проверки
```bash
npm install
npm run dev
npm run check
npm run build
npm run preview
```

`npm run check` проверяет синтаксис и выполняет автоматические проверки маршрутов, каталога, состава описания продукта и раскрытия ограничений лицензирования.

## Источник истины по СКОЛ CRM
Функции, модули, тарифы, feature IDs, формат лицензии, Device ID и ограничения сверяются с репозиторием:
`borzenkoofficial-lab/struktura-crm-source`, ветка `fix/skol-offline-licensing-2026-10`.

Ключевые исходники:
- `src/index.html` — реальные разделы интерфейса CRM.
- `src/main.cjs` и `src/renderer.js` — логика приложения и пользовательские сценарии.
- `src/license-core.cjs` — точная матрица `EDITION_FEATURES`.
- `docs/production-intelligence-order-radar.md` — источники и ограничения радара заказов.
- `docs/superpowers/specs/skol-offline-license.md` — модель лицензирования и её ограничения.

Сайт Struktura не используется как визуальный источник. Витрина имеет отдельную дизайн-систему СКОЛ Software Platform.

## Тарифы
- START — базовые клиенты, заявки, объекты и задачи.
- PRO — START + `engineering`, `finance`, `production`, `reports`.
- BUSINESS — PRO + `advanced_analytics`, `engineering_plans`, `order_radar`, `web_browser`.

Feature IDs сверяются с `EDITION_FEATURES` CRM; не следует добавлять маркетинговые обещания вне этой матрицы.

## Технические ограничения, раскрываемые на сайте
- Windows 10/11 x64, Electron desktop.
- Основная база SQLite хранится локально.
- Проверка лицензии Ed25519 и привязка Device ID выполняются локально.
- Веб-поиск и встроенный браузер требуют интернет-соединения.
- Офлайн-лицензию нельзя удалённо отозвать; при переносе нужен новый ключ для нового Device ID.
- `updatesUntil` хранится в лицензии, но в текущей реализации не блокирует обновления.
- Количество устройств по одной покупке не может централизованно контролироваться полностью офлайн.
- Радар заказов запускается пользователем; выдача поисковых источников может быть неполной и должна проверяться.
- Подключение тарифа выполняется через менеджера. Платёжная интеграция и автоматическая выдача ключей не подключены.
